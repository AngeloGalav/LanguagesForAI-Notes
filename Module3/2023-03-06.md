### 2. Encoding of sets of data. 
We would like to find appropriate encodings (into binary strings) for the following discrete sets:
1. The set $Q$ of rational numbers
2. Disjoint union of N and $\{0,1\}^*$
	- The cardinality of the union is 4
3. Graphs, pairs in the form $(V, E)$, such that $V$ is a finite set of nodes, while $E$ is a subset of $V \times V$. 

Answers:
1. We can write Q as follows:
	$Q = \{\dfrac{z}{n} | z \in Z, n \in N, n > 0\}$
It is the sufficient to observe that Q can be seen as a set of pairs in the form $(z, n)$. Each of the two numbers can then be enconded as strings in one of the ways we know.  
$$
\lfloor z/n\rfloor = S_z m_z \# m_n
$$
where: 
- $S_z$ is the sign of the number
- $m_z$ is the string of $z$
- $m_n$ is the string of $n$ 
- $\#$ is the fraction sign

This encoding is not completely satisfactory, since the same number can be encoded in many ways. We can avoid this problem by stipulating that $gcd(z, n) = 1$. 
(we are imposing that $z$ and $n$ are _coprime_). 
Also, we should be careful about how we represent $m_z$ and $m_n$, since the encoding must be reasonably succint (meaning, not too long), e.g. the following is _not_ an acceptable encoding:
- 1 ---> 10
- 2 ---> 100
- 3 ---> 1000
This would increase the complexity of the enconding.  

>[!WARNING]
>Remember, the floor ($\lfloor \ \rfloor$) sign is regarded as the encoding sign.

We can then try to understand that the real problem in this case is the representation of the edges. 
There are at least two ways for representing the edges of the graph. 
- Adjecency matrix ($n \times n$ matrix of bits, 1 if there's an edge, 0 otherwise).
	- $|M| = \Theta(n^2)$
	- Not very memory efficient for sparse graphs.  
- Adjecency lists
	- You represent all the edges whose first component is a given node $i$ as a list, the whole set of edges thus becomes a list of lists, e.g.:
		- N = {1,2,3}

			- the second 3 is the A.L. for 3
			- $\beta$ is a new separator meant to separate the encoding of edges in the same adjecency list separated. 

# The Computational Model
Giving positive results about the feasibility of certain computation task is relatively easy: You implement your algorithm, you run it on a powerful machine, and that’s it! 

But how about _negative_ results? Which machine should we choose? If we choose one specific, concrete machine without relating to the other ones, then our _negative results_ would be vacuous (what if a more powerful machine comes out and can compute the stuff?). 
The only way out is to define a model of computation in the form of an _abstract machine_, keeping in mind that: 
- It should be as simple as possible, to facilitate proofs. 
- It must be able to simulate with reasonable overhead all physically realistic machines. 

There is a universally accepted model of computation, that we will take as our reference model, namely the __Turing Machine__. This part of the module is specifically about it.

#### The Turing Machine
![[turing_machine.png]]
This turing mahcine computes the decision function $f : \{0, 1\}∗ → \{0, 1\}$. 
The scratchpad works as the memory of the machine, since the arrows are bidirectional. 

The set of instructions to be followed is fixed (and should work for every input $x$), and finite (like all algorithms should be).
The same instruction can be used potentially many times.
Every instruction proceeds by:
- Reading a bit of the _input_; 
- Reading a symbol from the _scratchpad_; 

The separation between Scratchpad and Instructions allows the Instructions to be immutable. 

and based on that decide what to do next, namely: 
- either _write_ symbol to the scratchpad, and proceed to another instruction; 
- or _declare the computation finished_, by stopping it and outputting either 0 or 1.

##### Run time in Turing machines 
In Turing machine, the run-time is very easy to define. 
- The running time of this machine/process/algorithm on $x$ is simply _the number of these basic instructions_ which are _executed_ on a certain input $x$. 
- We say that the machine runs in time $T(n)$ if it performs _at most_ $T(n)$ instructions on _input_ _strings of length_ $n$.
	- $T(n)$ can be a linear function, an exponential function etc...
- The model is _robust_ to many tweaks in the definition, (e.g. changing the alphabet, allowing multiple scratchpads rather than one): the simplest model can simulate the more complicated with a _polynomial overhead_ in time. 
- Since there are finitely many instructions, __machine descriptions__ can _be encoded as binary strings themselves_.
- Given a string $α$, we indicate as $M_α$ the Turing Machine $α$ encodes. 
- There is a so-called __Universal Turing Machine__ $U$, ==which simulates any other Turing Machine given its string representation==: from a pair of strings $(x, α)$, the machine $U$ simulates the behaviour of $M_α$ on $x$. 
- The simulation is very efficient: if the running time of $M_α$ were $T(|x|)$, then $U$ would take time $O(T(|x|) log T(|x|))$. 
- There are functions $f : \{0, 1\}^∗ → \{0, 1\}$ which are intrinsically uncomputable by Turing Machines, and this can be proved formally. 
	- This has intimate connections to Gödel’s famous incompleteness theorem.
